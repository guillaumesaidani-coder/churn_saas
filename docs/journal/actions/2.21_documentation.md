# 2.21 Documentation de référence dans `docs/`, coffre Obsidian (2026-09-29)
**Constat du formateur** : une solution sans la documentation qui va avec est de moins en moins
tolérée ; la qualité de la documentation compte pour la certification. **Outil retenu** :
Obsidian, pour rédiger et naviguer, avec une contrainte : le jury lit la documentation **sur
GitHub**. Tout est donc en Markdown standard, lisible des deux côtés.

**Réglages Obsidian** (le dépôt entier est le coffre) :
- liens Markdown standard et chemins relatifs (`useMarkdownLinks`, `newLinkFormat: relative`) :
  cliquables sur GitHub ;
- dossiers exclus de l'index : `Livrables/`, `reports/`, `scratchpad/`, `dist/`, données brutes ;
- seul `.obsidian/app.json` est versionné ; l'état des fenêtres reste propre au poste (`.gitignore`).

**Structure créée** (point d'entrée : `docs/index.md`) :

| Dossier | Contenu |
|---|---|
| `cadrage/` | Besoin et solution ; **une note par décision D1 à D15** avec son statut réel ; hypothèses H01 à H05 |
| `donnees/` | Sources et empreintes, dictionnaire (généré depuis l'énoncé et la base de connaissance), pipeline et lignage, préparation, RGPD et équité |
| `modeles/` | **Model cards v2** churn et CLV (il n'existait que les v1), protocole expérimental, système de décision |
| `explicabilite/` | Base de connaissance, méthode, contrôles, guide de lecture pour les CSM |
| `exploitation/` | Architecture v2 (remplace le DAT v1), contrat d'API, guide de démarrage, runbook, supervision |
| `qualite/` | Cahier de tests v2 (129 tests, vérifications du notebook, CI), intégration continue |
| `journal/` | Ce journal, **découpé** en une note par étape, texte inchangé (vérifié par script) |
| `archives/v1/` | DAT, guide d'expérimentation et cahier de tests v1, déplacés tels quels avec un bandeau « historique » |

**Méthode.** Chaque chiffre vient du notebook exécuté ou d'un artefact du dépôt (manifestes,
métriques) ; les exemples d'explication et de réponse de l'API sont des sorties réelles. Deux
affirmations ont été vérifiées avant d'être écrites :
- lancée sans `MODEL_DIR`, l'API charge le modèle v1 et répond `503 Modèle non conforme`, à
  cause des leurres : c'est documenté comme piège dans le contrat d'API et le guide de démarrage ;
- les hypothèses H02 à H04 ne figurent pas dans le notebook : elles viennent du document de
  cadrage (non publié), cité comme source.

**Deux points à corriger dans le notebook**, relevés en rédigeant (non modifiés, pour ne pas
toucher au livrable exécuté sans ton accord) :
1. **D4** annonce un rapport de coût FN/FP « de 45:1 à plus de 1 000:1 » ; avec la CLV médiane, on
   obtient 46:1 à 138:1, valeurs qu'utilise d'ailleurs l'analyse de coût du §9.5 (note
   [D4](../../cadrage/decisions/D04.md)).
2. La page de garde indique la date du 23 septembre, alors que le notebook a été réexécuté le
   28 septembre (la cellule d'environnement affiche la vraie date d'exécution).

**Suppressions** : `JOURNAL_MLOPS.md` (remplacé par `docs/journal/`), et à la racine
