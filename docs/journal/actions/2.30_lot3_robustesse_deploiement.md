# 2.30 Lot 3 : robustesse, sécurité et déploiement continu (2026-10-03)

**Pourquoi.** Fermer les failles faciles à pointer en soutenance (probabilités non vérifiées,
entrées de l'API non contrôlées, modèle servi non relié à celui qui a été évalué, clé API par
défaut, pas de lint) et livrer automatiquement chaque version validée : l'indicateur C6 de la
grille (« processus de livraison et de déploiement continu ») n'était pas couvert.

**A3.1 Calibration : on ne recalibre pas.** Erreur de calibration moyenne par déciles (ECE) :
4,5 points sur le test, 1,3 en validation croisée. Recalibration de Platt : Brier 0,1229 ;
isotonique : 0,1238 ; sans recalibration : 0,1230. Aucun gain : les probabilités brutes de la
régression logistique sont conservées. L'ECE est ajoutée aux métriques suivies (sans seuil : sur
100 comptes par décile, l'écart d'un décile peut venir du hasard). D14 et la
[model card](../../modeles/model_card_churn_v2.md) citent ce résultat.

**A3.2 Entrées de l'API validées.** [`src/validation.py`](../../../src/validation.py) : variable inconnue
du modèle, texte pour une variable numérique (ou l'inverse), valeur physiquement impossible
(nombre négatif, `csat` hors de 1 à 5, plus de 12 retards sur 12 mois, taux hors de 0 à 100 %)
donnent une réponse 422 qui liste les erreurs, avant tout calcul. Une valeur manquante, une valeur
inhabituelle ou une modalité inconnue restent acceptées, avec un avertissement dans l'explication.
Garde-fou testé : aucune valeur du Gold v2 n'est refusée.

**A3.3 Le modèle servi est celui qui a été certifié.** Le notebook écrira désormais, dans
`model_manifest.json`, l'empreinte SHA-256 des deux modèles qu'il a évalués (cellule modifiée,
effective au rejeu du lot 4). L'API compare ces empreintes aux fichiers chargés : différence ->
`/ready` en 503. La porte de qualité de la CI fait la même vérification. Tant que le manifeste ne
contient pas d'empreintes, `/ready` répond `empreintes_verifiees: false`.

**A3.4 Sécurité.** Plus de clé par défaut : sans `API_KEY`, l'API reste fermée (503) et Compose
refuse de démarrer ; clé comparée en temps constant ; identifiant client borné ; ports Compose
publiés sur `127.0.0.1`. Analyse des menaces : [sécurité (STRIDE)](../../exploitation/securite.md),
reliée depuis l'index de la documentation.

**A3.5 Lint en CI.** `ruff check .` dans le job `tests` (règles par défaut, [`ruff.toml`](../../../ruff.toml)) ;
trois écarts corrigés dans d'anciens tests (imports et variable inutilisés).

**A3.6 Déploiement continu.** Sur un push sur `main`, une fois le modèle évalué et `/ready` vérifié,
le job `docker` publie l'image testée sur `ghcr.io/guillaumesaidani-coder/churn_saas`, taguée par
les 12 premiers caractères du commit et `latest`. Le README et le guide de démarrage indiquent
comment la tirer. La livraison s'arrête au registre : aucun serveur n'est déployé.

**Tests.** 25 de plus, 214 au total : `test_validation.py` (14), 11 dans `test_api.py`.

**À vérifier après publication.** Le paquet GHCR contient le Gold v2 et les modèles : vérifier sa
visibilité dans les réglages du paquet. Le jeu de données est celui de l'énoncé, sans donnée
nominative ; la clé de pseudonymisation n'est pas dans l'image.
