# 2.24 Rejeu officiel de la v2.1, vérification de la documentation, publication (2026-09-30)
**Rejeu.** `dvc repro -s certification` avec MLflow sur DagsHub : notebook exécuté sans erreur,
les 10 vérifications finales passent (§15.3), 134 tests verts, `dvc status` à jour. Runs MLflow :
`a3dab54567c04e428ef9138d3256979f` (churn) et `319eaeb4f25d48acbddc612fcb98dc54` (CLV). Les
métriques officielles sont celles de la note 2.23 (PR-AUC test 0,748, seuil D9 0,2832, rappel
82,5 %).

**Documentation vérifiée contre ce rejeu.** Chaque chiffre de `docs/` a été comparé aux sorties du
notebook exécuté ; l'exemple de réponse de l'API a été rejoué sur le modèle v2.1. Quatre
corrections :
- écart de la décomposition exacte : 2,2 × 10⁻¹⁵ (et non 3,6, valeur v2.0) ;
- scoring de 5 000 comptes : 0,06 s (et non 0,08 s) ;
- runbook : `load_raw` attend un `Path`, pas une chaîne ; l'exemple aurait échoué ;
- model card churn : le tableau des plus forts coefficients omettait le taux d'adoption et le
  délai du support, qui devancent les retards en v2.1.

**Publication.**
- Commits `ac754a9` (code, base de connaissance, tests, notebook réexécuté, manifestes,
  `dvc.lock`) et `2bf5afa` (documentation `docs/`, Obsidian, retrait des fichiers racine).
- `dvc push` d'abord (19 fichiers : modèles, Gold et figures v2.1), puis `git push` vers GitHub
  et DagsHub.
- CI verte ([run 36745430348](https://github.com/guillaumesaidani-coder/churn_saas/actions/runs/36745430348)) :
  tests, `dvc pull` depuis DagsHub, construction de l'image et `/ready` sur le modèle v2.1.

**Leçon : deux sessions sur le même dépôt.** Une autre session modifiait le code pendant que
celle-ci préparait le commit. Le commit a été reporté jusqu'au rejeu du pipeline, pour que
`dvc.lock` corresponde au code committé. La surveillance a été faite sur les dates des fichiers,
sans commande DVC : `dvc status` prend le verrou du dépôt et aurait pu faire échouer un
`dvc repro` lancé en parallèle.
