# D8 — Critère d'acceptation du modèle

*Point de contact métier n°3.*

## Décision

Le modèle doit battre une **baseline métier simple** d'au moins **+0,15 de PR-AUC**.

## Justification

Un modèle n'a de valeur que s'il fait nettement mieux qu'une règle que le métier pourrait appliquer sans IA.

**Ce que D8 mesure.** La PR-AUC juge la **qualité du classement par risque** de tous les comptes,
pas la décision : celle-ci (150 appels sur 5 000, triés par probabilité × valeur) se juge sur la
perte captée ([système de décision](../../modeles/systeme_de_decision.md), notebook §9.8).

## Où elle est appliquée

- Baseline métier, reformulée sans la variable de fuite : `score = − ancienneté / 36 − intégrations / 16 + jours_depuis_connexion / 200`.
- Résultat sur le test (modèle v2.1) : PR-AUC 0,748 contre 0,593, soit **+0,154** : respecté, avec une marge faible ([`metrics.json`](../../../data/model_v2/metrics.json), champ `critere_D8_respecte`).
- Incertitude (notebook §12.1) : intervalle de confiance à 95 % du gain de **+0,108 à +0,202** ;
  41 % des tirages bootstrap passent sous +0,15. Le critère est tenu sur ce test, sans être acquis.
- Sensibilité à la règle de référence (notebook §8.4) : une règle qui ajoute la satisfaction client
  (CSAT) atteint 0,674 en validation croisée ; l'écart du modèle tombe à **+0,109** (+0,158 face à la
  règle D8 dans les mêmes conditions). Le modèle classe mieux par risque que toute règle testée.
- Vu de la décision, le modèle et la règle D8 calibrée font jeu égal sur la perte captée (47 % et
  48 % à 3 %) ; le modèle apporte la précision des appels (69 % contre 40 %), des probabilités
  calibrées et l'explication (notebook §9.8).
- Critère de promotion de tout nouveau modèle ([ré-entraînement](../../exploitation/runbook.md)) : vérifié pour un challenger par `scripts/challenger.py`, et pour le modèle en service à chaque push par la CI (`scripts/evaluer_modele.py`).

## Statut

Respectée sur le test (+0,154), avec un intervalle de confiance qui contient le seuil.
